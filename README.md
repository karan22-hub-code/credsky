# SKY CRED

**Check the sky's credit score before you step out.**

SKY CRED is a lightweight, single-page weather application built with semantic HTML, CSS and vanilla JavaScript. It loads live current conditions from WeatherAPI, translates them into a plain-language verdict, and exposes the actual API response in a developer JSON viewer.

> SKY CRED is a playful weather interpretation. The “sky score” is generated by this application and is **not** a real credit score.

## Architecture

```
index.html          Page structure and accessible UI landmarks
styles.css          Visual system, responsive layout and motion
app.js              UI state, WeatherAPI client, interpretation and JSON viewer
api/weather.js      Vercel serverless proxy that keeps the API key server-side
vercel.json         Serverless duration and security headers
.env                Local-only WeatherAPI key (ignored by Git)
.env.example        Safe placeholder for local setup
```

The browser calls `GET /api/weather?city=<city>` on the same origin. The serverless function calls WeatherAPI's `/v1/current.json` endpoint with the private `WEATHER_API_KEY`, then forwards a successful upstream body unchanged. This means the raw JSON shown in the UI is the actual WeatherAPI response, not a client-side reconstruction.

## Local development

Requirements: Node.js 20+ and a WeatherAPI key.

```bash
# 1. Install the Vercel CLI if needed
npm install -g vercel

# 2. Copy the environment template and add your key
cp .env.example .env

# 3. Run the static app + serverless function locally
vercel dev
```

Or, with no global install:

```bash
npx vercel dev
```

Open the local URL printed by Vercel. The app cannot be tested by opening `index.html` directly because the `/api/weather` serverless function is required for live data.

### Environment variable

```env
WEATHER_API_KEY=your_weatherapi_key_here
```

`.env` is intentionally excluded by `.gitignore`. The key is never included in `index.html`, `app.js` or any browser bundle. For production, add the same variable to the Vercel project's environment variables (Production, Preview and Development).

## Weather interpretation

The personality is recalculated on every successful request using temperature, condition text and wind speed.

### Thresholds

| Personality | Rule |
| --- | --- |
| Freeze Frame | `temp_c <= 8` |
| Rain Check | Condition text contains rain, drizzle, showers, thunder or thundery |
| Sun Alert | `temp_c >= 35` |
| Breezy Mode | `wind_kph >= 35` |
| Perfect Day | All other conditions |

### Overlap priority

1. Freeze Frame
2. Rain Check
3. Sun Alert
4. Breezy Mode
5. Perfect Day

This means a cold, rainy day is interpreted as Freeze Frame, while a hot, windy day is interpreted as Sun Alert. The sky score is derived from the same temperature, condition and wind inputs, with a small haze/cloud adjustment, and is capped at 5–99. It is an application-generated interpretation only.

## API contract

### `GET /api/weather?city=Mumbai`

Successful responses use HTTP 200 and return WeatherAPI's JSON body exactly as received. The frontend validates the required fields before replacing the current weather.

Error responses use a structured body:

```json
{
  "error": {
    "type": "city_not_found",
    "message": "City not found. Check the spelling and try again."
  }
}
```

Mapped error types include `city_not_found`, `configuration_error`, `rate_limited`, `service_unavailable`, `timeout` and `validation_error`.

The serverless function does not forward the API key, accepts only `GET`, times out upstream requests after 8.5 seconds, and sends no-store cache headers.
